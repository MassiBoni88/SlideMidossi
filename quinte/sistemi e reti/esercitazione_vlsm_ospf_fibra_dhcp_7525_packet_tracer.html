Esercitazione di laboratorio — Due palazzine in fibra con OSPF e DHCP ridondato 75/25

Sottoreti VLSM, dorsale in fibra ottica, routing dinamico OSPF, due server DHCP con relay agent e regola 75/25

Cisco Packet Tracer 5ª ITT Informatica — Sistemi e Reti Durata: 1 h 50 min Punteggio: 100

Scenario

Il Poliambulatorio San Luca occupa due palazzine distanti circa 400 m. Nella palazzina A si trovano gli AMBULATORI e l'ACCETTAZIONE, collegati al router R1; nella palazzina B si trovano gli UFFICI e il CED, collegati al router R2. I due router sono uniti da una dorsale in fibra ottica: su entrambi va installato un modulo con porta in fibra. Al poliambulatorio è stato assegnato il blocco 172.20.10.0/24, da suddividere con la tecnica VLSM.

Per garantire la continuità del servizio, gli indirizzi sono distribuiti da due server DHCP, uno per palazzina, che si fanno da backup a vicenda con la regola 75/25: per ogni LAN, il server della stessa palazzina distribuisce il 75% degli indirizzi e l'altro server il restante 25%. Perché un server possa servire anche le LAN in cui non si trova, i router fanno da relay agent. Le tabelle di routing vengono costruite dinamicamente da OSPF (processo 1, area 0).

Montaggio del modulo in fibra (su R1 e poi su R2)

Monta i moduli prima di configurare i router. Per inserire un modulo il router va spento, e lo spegnimento cancella la configurazione non salvata.
  1. Clic sul router → scheda Physical.
  2. Spegni il router con l'interruttore di alimentazione disegnato sullo chassis: la spia verde si spegne.
  3. Nell'elenco MODULES seleziona HWIC-1GE-SFP e trascinalo nello slot EHWIC 1.
  4. Riaccendi il router con lo stesso interruttore.
  5. Verifica il nome della nuova porta: scheda Config → INTERFACE. Deve comparire GigabitEthernet0/1/0.
Il nome dell'interfaccia dipende dallo slot: 0/1/0 = slot EHWIC 1, 0/0/0 = slot EHWIC 0. Se compare GigabitEthernet0/0/0 hai usato lo slot sbagliato: spegni il router, trascina il modulo fuori dallo slot e reinseriscilo nell'altro.

Parte 3 — Indirizzamento di router e server GUI 10 min · 10 punti

Convenzioni da rispettare

  1. L'interfaccia del router in una LAN prende il primo host della rete (è il default gateway della LAN).
  2. Ogni server DHCP prende il secondo host della propria rete.
  3. Sulla fibra, R1 prende il primo host e R2 il secondo.
  4. I PC per ora non si toccano: riceveranno l'indirizzo dal DHCP nelle Parti 5 e 6.

Procedura

  1. Router: Config → GLOBAL → Settings, imposta Hostname (R1 o R2). Poi Config → INTERFACE → GigabitEthernet…: Port Status su On, indirizzo IP e subnet mask. Ricordati anche della porta in fibra GigabitEthernet0/1/0.

Il default gateway dei due server è obbligatorio. Senza, un server non riesce a rispondere alle richieste che arrivano dalle altre LAN e il backup non funzionerà.

Parte 4 — Routing dinamico OSPF CLI 20 min · 20 punti

Con OSPF ogni router comunica ai vicini le reti a cui è collegato e costruisce da solo la tabella di routing: non serve scrivere rotte statiche. Parametri da usare: processo 1 e area 0.

Wildcard mask. Nel comando network la rete si indica con l'indirizzo di rete e la wildcard, che si ottiene sottraendo la subnet mask da 255.255.255.255.
Esempio: per una /29 (255.255.255.248) la wildcard è 0.0.0.7.

Parte 5 — Due server DHCP con regola 75/25 GUI 30 min · 25 punti

Regola 75/25. Per ogni LAN, il server della stessa palazzina è il principale e distribuisce il 75% degli indirizzi; l'altro server distribuisce il restante 25% come backup. I due range non devono sovrapporsi, perché i server non si scambiano informazioni sugli indirizzi già assegnati. Ogni server avrà quindi quattro pool, uno per LAN.

Procedura

  1. Su ciascun server: Services → DHCP, Service su On.
  2. serverPool: selezionalo nell'elenco in basso, modifica i campi e premi Save.
  3. Pool nuovi: scrivi il nome in Pool Name, compila i campi e premi Add (non Save, altrimenti sovrascrivi il pool selezionato). Ripeti per i tre pool.

  5. Sui sei PC: Desktop → IP Configuration → seleziona DHCP.
Trappola di Packet Tracer: quando cambi lo Start IP Address, il programma può ricalcolare da solo Subnet Mask (proponendo 255.255.255.0) e Maximum Number of Users. Con VLSM tutte le reti stanno nello stesso /24: se lasci la maschera proposta, i pool si sovrappongono e il server può assegnare l'indirizzo dal pool sbagliato. Ricontrolla sempre questi due campi prima di Save o Add.

Parte 6 — Relay agent e prova di backup CLI 15 min · 20 punti

Il DHCPDISCOVER del client è un broadcast e i router non inoltrano i broadcast. Il comando ip helper-address, configurato sull'interfaccia che riceve il broadcast del client, trasforma il router in relay agent: la richiesta viene inoltrata in unicast all'indirizzo indicato e il router scrive nel campo GIAddr l'IP della propria interfaccia. Il server usa il GIAddr per capire da quale subnet arriva la richiesta e scegliere il pool giusto.
Con due server, sulla stessa interfaccia si possono configurare più righe ip helper-address: il router inoltra la richiesta a ciascun server indicato.

Interfacce dei router

Per ogni interfaccia individua quali server DHCP il router deve raggiungere: nessuno, uno o due.

Il relay si configura solo da CLI: in Packet Tracer non esiste un campo della GUI per ip helper-address. 

R1> enable
R1# configure terminal
R1(config)# interface <interfaccia>
R1(config-if)# ip helper-address <primo server DHCP>
R1(config-if)# ip helper-address <secondo server DHCP, se serve>
R1(config-if)# exit
! ripeti per ogni interfaccia che ne ha bisogno, poi fai lo stesso su R2
R1(config)# end
Con entrambi i server accesi, se il relay inoltra la richiesta a due server il client accetta la prima offerta che riceve. Se un PC riceve un indirizzo del 25% anche con entrambi i server accesi, non è un errore: ha semplicemente risposto per primo il server di backup.

D7Prova di backup. Spegni il servizio DHCP su SRV-DHCP-A e rinnova l'indirizzo di PC-AMB1. Quale server risponde e da quale range arriva l'indirizzo? Grazie a quale informazione quel server sceglie il pool giusto?

Punto di controllo:
  • Su ogni PC: IP Configuration → Static e poi di nuovo DHCP. Tutti e sei i PC ricevono un indirizzo della propria LAN con il gateway corretto.
  • Backup palazzina A: SRV-DHCP-A → Services → DHCP su Off. Su PC-AMB1 ipconfig /release e poi ipconfig /renew: riceve un indirizzo del 25% degli AMBULATORI e ipconfig /all indica SRV-DHCP-B come server DHCP. Poi rimetti il servizio su On.
  • Backup palazzina B: stessa prova spegnendo SRV-DHCP-B e rinnovando l'indirizzo di PC-UFF1: riceve un indirizzo del 25% degli UFFICI da SRV-DHCP-A. Poi rimetti il servizio su On.
