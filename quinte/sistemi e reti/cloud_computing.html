Cos'è il Cloud Computing?

01
☁️ Il cloud computing è l'erogazione di risorse informatiche (server, storage, software, rete) via Internet, on demand, con pagamento basato sul consumo effettivo.

✅ Caratteristiche NIST

  • On-demand self-service — risorse senza intervento umano
  • Accesso via rete — da qualsiasi dispositivo
  • Resource pooling — risorse condivise e dinamiche
  • Elasticità rapida — scala su e giù in minuti
  • Misurazione — si paga solo ciò che si usa

🏗️ I due grandi temi

  • Tipi di cloud — chi possiede e controlla l'infrastruttura: Private, Public, Community, Hybrid
  • Modelli di servizio — cosa il cloud offre in affitto: SaaS, DaaS, HaaS, PaaS, IaaS
💡 I due concetti sono indipendenti: puoi avere un SaaS su private cloud o su public cloud.

I 4 tipi di Cloud — Panoramica

02
🔒

Private Cloud

Infrastruttura dedicata a una sola azienda. Massimo controllo e sicurezza. Costi elevati.

🌍

Public Cloud

Infrastruttura del provider, condivisa tra tutti i clienti. Pay per use. Zero hardware da comprare.

👥

Community Cloud

Condiviso tra più organizzazioni con interessi comuni (es. ospedali, università, PA).

🔀

Hybrid Cloud

Combina private + public. Dati sensibili in casa, carichi variabili sul cloud pubblico.

📌 Il Multi-cloud usa due o più cloud distinti (es. AWS + Google Cloud) contemporaneamente.

Private Cloud

03

🔒 Definizione

Ambiente cloud dedicato esclusivamente a un'unica organizzazione. Può essere fisicamente in sede (on-premise) o ospitato da un provider esterno, ma con pieno controllo dell'azienda su sicurezza e infrastruttura.

🏗️ Come si realizza

  • Hypervisor (bare metal): VMware ESXi, Hyper-V, KVM
  • Software di gestione: OpenStack, VMware vCenter
  • Portale self-service per gli utenti finali
  • VLAN per isolare i reparti · VPN per accesso remoto
✅
Pro: massimo controllo, sicurezza, conformità normative (GDPR, settore bancario/sanitario)
❌
Contro: costi elevati, serve un reparto IT dedicato, scalabilità limitata dall'hardware fisico
💡 ⚠️ Un server FTP aziendale in LAN NON è un private cloud: manca elasticità, self-service, resource pooling e misurazione del consumo.

Public Cloud

04
🌍 L'infrastruttura è di proprietà del provider ed è condivisa tra migliaia di clienti. L'utente paga solo ciò che consuma (pay per use) e non possiede nulla.

Community Cloud

05
👥 Cloud condiviso tra più organizzazioni con interessi, normative o obiettivi comuni. Non è pubblico (non ci accede chiunque), non è privato (appartiene a un gruppo).

🏥 Esempi concreti

  • Ospedali di una regione che condividono cartelle cliniche
  • CINECA — consorzio università italiane, calcolo condiviso
  • SPID / PagoPA — infrastruttura condivisa PA italiana
  • Banche — sistemi di pagamento interbancari

⚖️ Perché non usare il public?

  • Dati sensibili (medici, legali, fiscali)
  • Vincoli GDPR e normative di settore
  • Necessità di condivisione controllata tra enti
  • Costi divisi tra i partecipanti
🏢 Analogia: un condominio — il cortile e l'ascensore sono condivisi tra i condomini, ma un estraneo non può entrare.

Hybrid Cloud

06
🔀 Combina private + public cloud in un sistema integrato. L'azienda gestisce in casa ciò che è critico e "sfora" sul public cloud quando serve più potenza (cloud bursting).

🏠 Nel Private (in casa)

  • Dati personali clienti (GDPR)
  • Database transazionali
  • Sistemi gestionali interni
  • Dati bancari / sanitari

☁️ Nel Public (fuori)

  • Sito web pubblico
  • App mobile
  • Picchi di traffico stagionali
  • Big data non sensibili

📦 Cloud Bursting — esempio Black Friday

SaaS — Software as a Service

09
💻 Il provider eroga un software completo e pronto all'uso, accessibile via browser. L'utente non installa nulla sul proprio PC.

📱 Esempi

  • Gmail — email nel browser
  • Office 365 — Word/Excel online
  • Google Docs — scrittura collaborativa
  • Spotify — musica in streaming
  • Netflix — video in streaming

🔧 Cosa gestisce chi

  • ✅ Utente: usa il software
  • 🔧 Provider: tutto il resto (server, aggiornamenti, backup, sicurezza)
🎯 Ideale per piccole aziende senza reparto IT
💡 Il SaaS è l'evoluzione moderna della Presentation Virtualization: l'app gira su server remoto, l'utente vede solo l'interfaccia.

DaaS e HaaS

10
🗄️ DaaS — Data as a Service: il provider mette a disposizione solo i dati, accessibili da qualsiasi applicazione come se fossero su un disco locale.

📁 Esempi DaaS

  • iCloud Drive — file accessibili da Mac/iPhone come se fossero locali
  • Google Drive — stessa logica
  • Dropbox — cartella sincronizzata nel cloud
💡 Nel DaaS l'utente sceglie lui stesso l'applicazione con cui aprire i dati. Nel SaaS anche l'app è decisa dal provider.
⚙️ HaaS — Hardware as a Service: l'utente invia dati al provider, che li elabora con i suoi computer e restituisce i risultati.

🤖 Esempi HaaS

  • Claude / ChatGPT — testo inviato → elaborazione su server enormi → risposta ricevuta
  • Google Photos — foto inviate → riconoscimento AI → risultati
  • Render farms — file 3D inviati → rendering → video ricevuto
💡 Ogni volta che usi un'AI online stai usando HaaS: la potenza di calcolo è del provider, non tua.

PaaS — Platform as a Service

11
🏗️ Il provider offre una piattaforma completa per sviluppare, testare e distribuire applicazioni: server, database, librerie, ambienti di esecuzione. Lo sviluppatore si concentra solo sul codice.

🛠️ Esempi PaaS

  • Aruba Jelastic Cloud (citato dal libro)
  • Heroku — carichi il codice, lui fa girare tutto
  • Firebase (Google) — database + auth + hosting già pronti
  • Vercel / Netlify — deploy di app web istantaneo

🔧 Cosa gestisce chi

  • ✅ Sviluppatore: scrive il codice, definisce la logica
  • 🔧 Provider: server, OS, database, rete, scalabilità, backup
🎯 Ideale per startup e sviluppatori che vogliono concentrarsi sul prodotto
📌 PaaS vs SaaS: nel SaaS usi un'app già fatta; nel PaaS costruisci la tua app usando la piattaforma del provider.

IaaS — Infrastructure as a Service

12
🖥️ Il provider affitta solo l'hardware virtuale grezzo: CPU, RAM, disco, rete. L'utente ci installa sopra tutto il software, incluso il sistema operativo. Massima flessibilità, massima responsabilità.

⚡ Esempi IaaS

  • AWS EC2 — VM grezze su Amazon
  • Google Compute Engine
  • Azure Virtual Machines
  • Aruba Cloud (italiano)
  • Hetzner (europeo, economico)

🔧 Cosa gestisce chi

  • ✅ Utente: OS, middleware, app, dati, sicurezza software
  • 🔧 Provider: solo hardware fisico, rete, datacenter
⚠️ Serve un reparto IT competente. Non è per tutti.
🔗 IaaS è legato al concetto di grid computing: risorse hardware condivise e assegnate on demand, non a prescindere dall'utilizzo effettivo.
