Ripasso — perché serve un Root Bridge

L3 · 03/16

Il problema: i loop

Per avere ridondanza colleghiamo gli switch con più percorsi. Ma un broadcast verrebbe inoltrato all'infinito lungo l'anello: il frame Ethernet non ha un TTL che lo fermi. È la broadcast storm.

La soluzione: un albero logico

STP lascia la rete fisica ridondante, ma blocca alcune porte: la rete logica diventa un albero senza cicli. Se un collegamento cade, una porta bloccata si riattiva.

  1. Elezione del root bridge: la radice dell'albero ← oggi
  2. Ogni altro switch sceglie la root port, il percorso più economico verso la radice
  3. Su ogni segmento c'è una designated port; le porte rimaste vengono bloccate
🔗 Nel Laboratorio 6 (Packet Tracer) il root è Switch5. I pallini arancioni sono le porte bloccate: Fa5/1 di Switch2 e Fa4/1 di Switch4 (p. 94).

Il Bridge ID (BID) — 8 byte

L4 · 04/16
Classico
Priority · 2 byte (16 bit)
MAC address di base · 6 byte (48 bit)
802.1Q moderno
Priority · 4 bit
Ext. System ID · 12 bit = VLAN
MAC address di base · 48 bit
Esempio
32768
+ 1 (VLAN 1)
00:11:22:33:44:55 → priorità mostrata: 32769

Le due regole

  1. Vince la priorità più bassa
  2. A parità di priorità, vince il MAC più basso

In una parola: vince il BID più basso.

La priorità

  • Predefinita: 32768
  • La sceglie l'amministratore, per esempio bassa sullo switch centrale
  • Solo multipli di 4096: 0, 4096 … 61440 (16 valori)

Il MAC di base

È il MAC dello switch come apparato (base MAC o chassis MAC), non quello di una singola porta. È univoco: garantisce che non ci siano pareggi.

💡 Perché 4096? Dei 16 bit di priorità, 12 servono ora per la VLAN: restano 4 bit regolabili, a passi di 212 = 4096. Nel codice di oggi usiamo la priorità «classica» a 16 bit, come il libro.

Cos'è una tupla

L4 · 06/16

Una sequenza ordinata e immutabile

  • Raggruppa più valori in un unico oggetto, tra parentesi tonde, separati da virgole
  • È ordinata: ogni valore ha una posizione (indice), a partire da 0
  • I valori possono essere di tipo diverso: qui un numero e una stringa
  • È immutabile: una volta creata non si possono cambiare, aggiungere o togliere elementi
bid = (24576, "00:11:22:33:44:44")
#        bid[0]          bid[1]
#      priorità           MAC

Tupla o lista?

La lista [ ] è una raccolta che cresce e cambia, per esempio l'elenco degli switch. La tupla ( ) è un «pacchetto» fisso di dati che stanno insieme: un BID, le coordinate (x, y), una data (giorno, mese, anno).

Provalo nel Terminale

Nel nostro programma le tuple sono 4

  • bridge_id = (data["priority"], data["mac"]): il BID
  • switches.items() dà coppie (nome, dati), spacchettate nel for
  • return (root_bridge, root_data): due valori restituiti insieme
  • name, data = result: spacchettamento del risultato

Confrontare tuple = la regola di STP

L4 · 07/16

Il trucco del libro

Rappresentiamo il BID come tupla (priority, mac). Con < Python confronta due tuple elemento per elemento: prima i due elementi in posizione 0; solo se sono uguali, passa a quelli in posizione 1.

È esattamente la regola di STP: niente if per gestire la parità.

I dati: un dizionario di dizionari

{"nome_switch": {"priority": int, "mac": str}}

switches["SwitchE"]["priority"]   # 24576

Provalo subito nel Terminale

$ python3
>>> (24576, "00:11:22:33:44:44") < (24576, "00:11:22:33:44:77")
True
>>> (24576, "00:11:22:33:44:77") < (28672, "00:11:22:33:44:00")
True
>>> exit()
💡 Nel secondo confronto vince il primo BID anche se il suo MAC (…77) è più alto: decide già la priorità, il MAC non viene neanche guardato.

Il programma 1/2 — la funzione

L4 · 09/16 
# RootBridgeElection.py - Unità 3, Laboratorio 4
# Simula l'elezione del Root Bridge dello Spanning Tree (STP)

def root_bridge_election(switches):
    """Elegge come root bridge lo switch con il Bridge ID più basso."""
    if not switches:
        return None

    root_bridge = None
    lowest_bridge_id = None

    for name, data in switches.items():
        # Controllo validità dei dati
        if "priority" not in data or "mac" not in data:
            print(f"Errore: dati mancanti per lo switch {name}")
            continue

        # Il Bridge ID come tupla: prima la priorità, poi il MAC
        bridge_id = (data["priority"], data["mac"])

        # Se è il più basso trovato finora, diventa il candidato root
        if lowest_bridge_id is None or bridge_id < lowest_bridge_id:
            root_bridge = name
            lowest_bridge_id = bridge_id
            root_data = data

    return (root_bridge, root_data) if root_bridge else None

Come ragiona

  • root_bridge e lowest_bridge_id partono da None: nessun vincitore ancora
  • Il for esamina uno switch alla volta con .items(): nome e dati
  • Se mancano priority o mac: messaggio e continue, si passa al successivo
  • Il BID è la tupla (priority, mac)
  • Se è il più basso visto finora, quello switch diventa il candidato root

Il punto debole: il MAC confrontato come testo

L4 · 12/16

Cosa succede

Le stringhe si confrontano carattere per carattere, secondo il codice di ogni carattere: 'B' = 66, 'a' = 97. Quindi per Python "BB" < "aa", anche se come numeri esadecimali BB > AA.

Altri casi che falsano il confronto: formati diversi come 0011.2233.4455 (Cisco) o 00-11-22-33-44-55 (Windows).

💡 Per STP il MAC è un numero di 48 bit, non un testo. Con i dati del libro funziona solo perché sono tutti scritti nello stesso formato e solo con cifre.

La correzione: MAC → numero

def mac_to_int(mac):
    """Converte un MAC in numero, qualunque sia il formato."""
    cifre = mac.replace(":", "").replace("-", "").replace(".", "")
    return int(cifre, 16)

# nel for, al posto della riga del libro:
bridge_id = (data["priority"], mac_to_int(data["mac"]))

int(cifre, 16) legge le 12 cifre in base 16. Con la correzione l'esperimento 4 elegge SwitchC, come deve.

2 · La priorità deve essere un multiplo di 4096

Suggerimento: l'operatore % dà il resto della divisione.

def priorita_valida(priority):
    return priority % 4096 == 0 and 0 <= priority <= 61440

# nel for, dopo il controllo dei dati mancanti:
if not priorita_valida(data["priority"]):
    print(f"Errore: priorità non valida per {name}")
    continue
