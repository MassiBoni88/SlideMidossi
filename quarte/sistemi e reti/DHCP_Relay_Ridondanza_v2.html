1 Obiettivi dell'esercitazione

Al termine di questa esercitazione lo studente sarà in grado di:

  • Spiegare il ruolo del DHCP Relay Agent in una rete segmentata
  • Configurare due server DHCP con pool primari (75%) e di backup (25%)
  • Usare la GUI di Packet Tracer per configurare IP, server e pool DHCP
  • Usare la CLI del router solo per il comando ip helper-address
  • Verificare il corretto funzionamento della ridondanza DHCP

2 Schema di rete e indirizzamento

La rete è composta da due LAN collegate da un router. Ogni LAN ha il proprio server DHCP: gestisce il 75% degli indirizzi della propria rete (da .3 a .190) e il 25% come backup per l'altra rete (da .191 a .254).

[Server0: 192.168.1.2] [Server1: 192.168.2.2] | | [Switch A] [Switch B] | | Fa0/0 (192.168.1.1) Fa0/1 (192.168.2.1) +------------[ ROUTER ]------------+ [PC-A1] [PC-A2] ... [PC-B1] [PC-B2] ...

Perché si parte da .3?Gli indirizzi .1 (router) e .2 (server DHCP) sono già assegnati staticamente. Il pool DHCP inizia da .3 per evitare conflitti di indirizzo.

3 Fase 1 – Creazione della topologia

Aprire Cisco Packet Tracer e costruire la rete trascinando i dispositivi nell'area di lavoro.

3.1 Aggiungere i dispositivi

  1. 1Network Devices → Routers: aggiungere un router 1941 (o 2811/2911).
  2. 2Network Devices → Switches: aggiungere due Switch 2960.
  3. 3End Devices → Server: aggiungere due Server. Rinominarli Server0 e Server1.
  4. 4End Devices → PC: aggiungere almeno due PC per ogni LAN.

3.2 Collegare i dispositivi con cavi Straight-Through

  • Router Fa0/0 → Switch A
  • Router Fa0/1 → Switch B
  • Server0 → Switch A  |  PC-A1, PC-A2 → Switch A
  • Server1 → Switch B  |  PC-B1, PC-B2 → Switch B

6 Fase 4 – Relay Agent sul Router (CLI)

Questa è l'unica fase che richiede la CLI: il comando ip helper-address non è disponibile nella GUI di Packet Tracer. Tutti gli altri parametri del router sono già stati impostati via GUI nella Fase 2.

Cliccare sul Router → tab CLI → premere Invio per accedere alla console.

6.1 Entrare in modalità di configurazione

Router CLI
Router> enable
Router# configure terminal

6.2 Relay sull'interfaccia Fa0/0 (LAN A)

Il router inoltrerà le richieste DHCP di LAN A a entrambi i server:

Router CLI – Fa0/0 (LAN A)
Router(config)# interface FastEthernet0/0
! Server0: primario per LAN A
Router(config-if)# ip helper-address 192.168.1.2
! Server1: ha il pool LAN_A_Backup (25% di backup)
Router(config-if)# ip helper-address 192.168.2.2
Router(config-if)# exit

6.3 Relay sull'interfaccia Fa0/1 (LAN B)

Router CLI – Fa0/1 (LAN B)
Router(config)# interface FastEthernet0/1
! Server1: primario per LAN B
Router(config-if)# ip helper-address 192.168.2.2
! Server0: ha il pool LAN_B_Backup (25% di backup)
Router(config-if)# ip helper-address 192.168.1.2
Router(config-if)# exit
Router(config)# end
📌
Perché due ip helper-address?Con due ip helper-address sulla stessa interfaccia il router invia la richiesta DHCP a entrambi i server contemporaneamente. Il PC accetta la prima DHCPOFFER ricevuta — normalmente quella del server primario, che ha il pool più grande e risponde più velocemente.

7 Fase 5 – Verifica del funzionamento

7.1 Verifica sui PC client

  1. 1PC → Desktop → IP Configuration: verificare che il campo IP Address sia nel range 192.168.x.3 – .190 (pool primario).
  2. 2Se il PC mostra ancora 0.0.0.0: cliccare Static, attendere 2 secondi, poi cliccare di nuovo DHCP per forzare una nuova richiesta.
  3. 3In alternativa aprire Desktop → Command Prompt e digitare ipconfig /all per vedere tutti i dettagli.

8 Fase 6 – Test della ridondanza

Verifica che il meccanismo di backup funzioni simulando il guasto del server primario.

8.1 Simulare il guasto di Server0 (primario LAN A)

  1. 1Cliccare su Server0 → Services → DHCP → impostare il servizio su Off.
  2. 2Su un PC della LAN A: Desktop → IP Configuration → cliccare Static, poi di nuovo DHCP.
  3. 3Verificare che il PC riceva un IP nel range 192.168.1.191 – 192.168.1.254 — erogato da Server1 tramite il pool LAN_A_Backup.

9 Domande di verifica

  1. Perché senza il relay agent i PC non riceverebbero un IP dai server DHCP di un'altra rete?
  2. Cosa succede se su un'interfaccia del router si configura un solo ip helper-address? La ridondanza funziona ancora?
  3. Quale protocollo trasporta i messaggi DHCP? Su quale porta UDP lavora il server?
  4. Se entrambi i server rispondono alla richiesta DHCP, come fa il client a scegliere quale offerta accettare?
  5. Come mai il pool primario inizia da .3 e non da .1? Cosa succederebbe se iniziasse da .1?
  6. Proponi un'alternativa al relay agent per distribuire indirizzi IP ai client di LAN A senza usare ip helper-address.
