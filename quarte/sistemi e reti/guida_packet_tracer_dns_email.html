Packet Tracer: server DNS e server Email — guida rapida

Un PC invia un'email a un altro scrivendo il nome del server di posta al posto dell'indirizzo IP

Cisco Packet Tracer 8.x Sistemi e Reti — ITT E. Midossi DNS · SMTP · POP3

Obiettivo

Alla fine del laboratorio Mario (PC0) invia un'email a Lucia (PC1) scrivendo il nome mail.midossi.lab al posto dell'indirizzo IP: il server DNS traduce il nome in indirizzo, il server Email consegna il messaggio.

I protocolli in gioco sono tre: DNS porta 53 risolve i nomi, SMTP porta 25 invia la posta al server, POP3 porta 110 la scarica dal server al client. Serve Cisco Packet Tracer 8.x; le voci di menu restano in inglese e nella guida le trovi scritte così, in grassetto.

Topologia e piano di indirizzamento

La rete è una sola LAN 192.168.10.0/24 con uno switch, due server e due PC; non serve un router, quindi il Default Gateway resta vuoto.

Lo switch mette tutti sulla stessa rete; il server DNS, evidenziato, risponde alle richieste di nomi di tutti gli altri.

Come costruirla

  1. Dal pannello dei dispositivi in basso a sinistra trascina nell'area di lavoro uno switch 2960 (Network Devices > Switches), due Server-PT e due PC-PT (End Devices).
  2. Collega ogni dispositivo allo switch con il cavo Copper Straight-Through (linea nera continua): sul PC o sul server scegli FastEthernet0, sullo switch la porta indicata in tabella.
  3. Rinomina i dispositivi con il nome della colonna Display Name: clic sul nome sotto l'icona, oppure Config > Settings > Display Name.
  4. Aspetta che i triangolini sui collegamenti diventino verdi; per non attendere premi Fast Forward Time in basso.

Passo 1 — Indirizzi IP statici Config

Ogni dispositivo riceve un IP fisso e usa 192.168.10.2 come DNS Server: senza questa voce il PC non sa a chi chiedere la traduzione dei nomi. Gli indirizzi si inseriscono dalla scheda Config in alto, che hanno sia i PC sia i server: l'indirizzo IP e la subnet mask nell'interfaccia FastEthernet0, gateway e DNS nelle impostazioni generali Settings.

I numeri nei cerchi corrispondono ai passi qui sotto; i campi evidenziati sono quelli da compilare.

  1. Clic sul dispositivo e, in alto, apri la scheda Config (ce l'hanno anche i Server-PT).
  2. Nella colonna di sinistra, sotto INTERFACE, seleziona l'interfaccia FastEthernet0.
  3. In IP Configuration scegli Static e compila IPv4 Address e Subnet Mask come nella tabella sopra.
  4. Sempre nella colonna di sinistra, sotto GLOBAL, apri Settings.
  5. In Gateway/DNS IPv4 scegli Static e scrivi DNS Server 192.168.10.2; Default Gateway resta vuoto.
  6. Chiudi la finestra: i valori si salvano da soli. Ripeti su tutti e quattro i dispositivi, server compresi.
In Packet Tracer l'interfaccia FastEthernet0 contiene solo indirizzo IP e subnet mask: Default Gateway e DNS Server valgono per tutto il dispositivo e per questo stanno in Settings.
Prima di andare avanti: da PC-Mario > Desktop > Command Prompt scrivi ping 192.168.10.3: se il server Email non risponde, ricontrolla indirizzi e cavi.

Passo 2 — Server DNS Services

Il server DNS custodisce un elenco di record «nome → indirizzo»: basta un record di tipo A perché i PC trovino il server di posta con il nome mail.midossi.lab.

I numeri nei cerchi corrispondono ai passi qui sotto; i campi evidenziati sono quelli da compilare.

  1. Clic sul server DNS > scheda Services > nella colonna di sinistra DNS.
  2. In alto imposta DNS Service su On: di default è Off ed è l'errore più comune.
  3. In Resource Records scrivi Name mail.midossi.lab, lascia Type su A Record, scrivi Address 192.168.10.3 e premi Add.
  4. Ripeti con Name dns.midossi.lab e Address 192.168.10.2 (facoltativo, serve per raggiungere il server DNS con il suo nome).
  5. Controlla che i due record compaiano nella tabella in basso; per correggerne uno selezionalo, modificalo e premi Save, per toglierlo Remove.
Il tipo A Record associa un nome a un indirizzo IPv4; un CNAME crea invece un alias, per esempio posta.midossi.lab → mail.midossi.lab.

Passo 3 — Server Email Services

Il server Email gestisce il dominio midossi.lab e le caselle dei due utenti, che avranno gli indirizzi mario@midossi.lab e lucia@midossi.lab (utente + @ + dominio).

Il pulsante Set e il pulsante + sono quelli che si dimenticano più spesso: senza di loro dominio e utenti non vengono salvati.
  1. Clic sul server MAIL > scheda Services > nella colonna di sinistra EMAIL.
  2. Verifica che SMTP Service e POP3 Service siano su On.
  3. In Domain Name scrivi midossi.lab e premi Set: senza Set il dominio non viene registrato.
  4. In User Setup scrivi User mario, Password 1234 e premi +.
  5. Ripeti con lucia / 1234. Gli utenti compaiono nell'elenco sotto; − elimina l'utente selezionato, Change Password ne cambia la password.

Passo 4 — Client di posta sui PC Desktop

Ogni PC ha già un programma di posta in Desktop > Email: va configurato una volta con i dati dell'utente e con il nome del server.

I due campi evidenziati sono quelli che fanno lavorare il DNS: il PC deve prima scoprire quale IP corrisponde a mail.midossi.lab.

Passo 5 — Verifica

Il laboratorio è riuscito quando nslookup restituisce 192.168.10.3 e Lucia riceve il messaggio di Mario.

A. Il DNS risponde

Da PC-Mario > Desktop > Command Prompt:

C:\>nslookup mail.midossi.lab
C:\>ping mail.midossi.lab

L'output di nslookup deve riportare Name: mail.midossi.lab e Address: 192.168.10.3; il ping deve ricevere risposta da 192.168.10.3.

B. Invio e ricezione

  1. Su PC-Mario, nella casella di posta, premi Compose.
  2. Scrivi To lucia@midossi.lab, Subject Prova, un breve testo e premi Send: in basso compare Send Mail Success.
  3. Su PC-Lucia premi Receive: il messaggio compare nell'elenco con Receive Mail Success. Selezionalo per leggerlo, Reply per rispondere.

C. Il percorso di una mail

I passaggi 1–3 avvengono quando Mario preme Send, i passaggi 4–7 quando Lucia preme Receive: prima di parlare con il server di posta, ogni PC chiede al DNS l'indirizzo di mail.midossi.lab.

Errori frequenti

Quasi tutti i problemi nascono da un interruttore rimasto su Off o da un campo scritto in modo diverso tra server e client.

Esercizio avanzato — due domini

Obiettivo: Mario (mario@midossi.lab) scrive ad Anna, che ha la casella su un secondo server di posta del dominio liceo.lab, in un'altra rete.

  1. Aggiungi un router 2911, un secondo switch e la LAN 192.168.20.0/24 con il server MAIL2 (192.168.20.3, dominio liceo.lab, utente anna) e PC-Anna (192.168.20.11). Collega con cavo Copper Straight-Through il primo switch alla porta GigabitEthernet0/0 del router e il secondo switch alla GigabitEthernet0/1.
  2. Su MAIL2 e PC-Anna inserisci indirizzo IP e subnet mask come al Passo 1, da Config > FastEthernet0.
  3. Configura le due interfacce del router, sempre dalla scheda Config (figura sotto):
    1. clic sul router > scheda Config in alto;
    2. nella colonna di sinistra, sotto INTERFACE, seleziona GigabitEthernet0/0;
    3. spunta Port Status: On, poi scrivi IPv4 Address 192.168.10.1 e Subnet Mask 255.255.255.0;
    4. ripeti con GigabitEthernet0/1: Port Status On, 192.168.20.1 / 255.255.255.0.
  4. Imposta il Default Gateway su tutti i dispositivi da Config > Settings: 192.168.10.1 nella prima LAN, 192.168.20.1 nella seconda.
  5. Sul server DNS aggiungi tre A Record: midossi.lab → 192.168.10.3, liceo.lab → 192.168.20.3, mail.liceo.lab → 192.168.20.3.
  6. Anche MAIL2 e PC-Anna usano 192.168.10.2 come DNS Server (Config > Settings).
Le interfacce del router sono spente di default: senza la spunta su Port Status: On il collegamento verso lo switch resta rosso e le due LAN non si vedono.
Perché i record con il solo nome del dominio: per consegnare la posta a un altro dominio, il server MAIL chiede al DNS l'indirizzo della parte dopo la @. Nelle reti reali questo compito spetta al record MX; in Packet Tracer si usa un record A con il nome del dominio.
