La memoria di un programma

SEZIONE 01

Quattro zone, quattro comportamenti

Quando il programma parte, il sistema operativo gli assegna della memoria divisa in regioni. A noi ne interessano soprattutto due: lo stack e lo heap.

CODICE
le istruzioni del programma
DATI STATICI
variabili globali e static: vivono per tutto il programma
STACK
variabili locali e parametri: nascono e muoiono con la funzione
HEAP
memoria chiesta a runtime con new: vive finché non fai delete
ⓘLo stack è gestito automaticamente dal compilatore. Lo heap lo gestisci tu: è questa la differenza che cambia tutto.

Il limite dell'allocazione statica

Finora la dimensione di ogni array l'hai decisa scrivendo il codice, cioè prima di sapere quanti dati arriveranno davvero.

// Come hai sempre fatto in terza:
const int MAX = 25;
Esopianeta catalogo[MAX];
int quanti = 0;

// Se ne cataloghi 3  -> sprechi 22 posti
// Se te ne servono 40 -> non ci stanno
// e il programma va modificato e ricompilato
⚠La dimensione di un array statico deve essere una costante nota alla compilazione. Non puoi scrivere cin >> n; e poi int v[n];: non è C++ standard.
➜La soluzione è chiedere la memoria mentre il programma gira, quando finalmente sai quanta ne serve. Per farlo serve un nuovo tipo di dato: il puntatore.

Il tipo puntatore

SEZIONE 02

Un'idea sola

Ogni variabile occupa delle celle di memoria, e ogni cella ha un indirizzo. Un puntatore è semplicemente una variabile che contiene un indirizzo invece di un valore normale.

OPERATORE
SIGNIFICATO
&x
l'indirizzo della variabile x
int* p
dichiara p: puntatore a un int
*p
il valore contenuto all'indirizzo p
⚠L'asterisco ha due significati diversi: nella dichiarazione int* p; vuol dire "p è un puntatore"; nell'uso *p = 5; vuol dire "vai all'indirizzo e lavora lì". Non confonderli.
int eta = 20;
int* p = &eta;   // p riceve l'INDIRIZZO di eta

cout << eta;    // 20        il valore
cout << &eta;   // 0x7ffee4  l'indirizzo
cout << p;      // 0x7ffee4  lo stesso indirizzo
cout << *p;     // 20        dereferenziazione

*p = 25;         // modifico eta ATTRAVERSO p
cout << eta;    // 25  -> eta e' cambiata!

Come leggerlo ad alta voce

int* p = &eta; si legge: "p è un puntatore a intero e vale l'indirizzo di eta".
*p = 25; si legge: "metti 25 nella cella puntata da p".

nullptr e gli errori classici

SEZIONE 02

Il puntatore "a vuoto"

nullptr è il valore convenzionale che significa "non punto a niente". Serve per dire che un dato non c'è ancora, o non c'è più.

int* p = nullptr;  // inizializzato a vuoto

// Prima di usarlo, si CONTROLLA sempre:
if (p != nullptr) {
  cout << *p;
} else {
  cout << "Nessun dato\n";
}
✓Regola pratica: un puntatore va sempre inizializzato, o con un indirizzo valido o con nullptr. Mai lasciarlo indefinito.
// ERRORE 1 — puntatore non inizializzato
int* q;          // contiene spazzatura
*q = 10;         // crash o danno silenzioso

// ERRORE 2 — confondere p e *p
int a = 5;
int* p = &a;
p = 10;          // NO: 10 non e' un indirizzo
*p = 10;         // SI: cosi' scrivo in a

// ERRORE 3 — dereferenziare nullptr
int* z = nullptr;
cout << *z;      // crash immediato
✗Il compilatore non ti avvisa di questi errori: la sintassi è corretta. Te ne accorgi solo quando il programma si blocca, magari molto dopo il punto in cui hai sbagliato.

Puntatori e array

SEZIONE 02

Il nome di un array è un indirizzo

In C++ il nome di un array equivale all'indirizzo del suo primo elemento. Array e puntatori sono quindi parenti stretti.

int v[5] = {10, 20, 30, 40, 50};

cout << v;        // indirizzo di v[0]
cout << &v[0];   // lo stesso indirizzo

int* p = v;      // legale: nessuna &
cout << *p;       // 10
cout << *(p+2);   // 30  aritmetica dei puntatori
cout << p[2];     // 30  forma equivalente
ⓘp+1 non somma 1 byte: avanza di un elemento, cioè di sizeof(int) byte. Il compilatore fa il conto per te.

Il mistero risolto

Ricordi le funzioni che ricevevano un array, come cercaPerStella(Esopianeta cat[], int n, ...)? Ora puoi capire cosa succedeva davvero.

// Queste due righe sono la STESSA cosa
void f(int v[]);
void f(int* v);   // il compilatore traduce cosi'
ⓘQuando passi un array a una funzione non viene copiato: viene passato il suo indirizzo. Ecco perché serviva anche il parametro n — dall'indirizzo da solo è impossibile sapere quanti elementi ci sono.
⚠Conseguenza importante: se una funzione modifica l'array che riceve, la modifica si vede anche nel main. Una struct passata per valore, invece, viene copiata per intero — array interni compresi.

Allocazione dinamica: new e delete

SEZIONE 03

Chiedere memoria a runtime

new chiede allo heap una zona di memoria e restituisce il suo indirizzo. Quella zona resta tua finché non la restituisci con delete.

int* p = new int;   // chiedo spazio per un int
*p = 42;               // lo uso tramite il puntatore
cout << *p;            // 42

delete p;              // restituisco la memoria
p = nullptr;           // buona pratica: azzero p

// con valore iniziale, in una riga sola
int* q = new int(7);
delete q;
ⓘLa variabile creata con new non ha un nome: l'unico modo per raggiungerla è il puntatore. Se perdi il puntatore, perdi il dato.

Le tre regole d'oro

  • A ogni new deve corrispondere un delete.
  • A ogni new[] deve corrispondere delete[], con le parentesi.
  • Dopo delete, metti il puntatore a nullptr.
STACK
HEAP
int x = 5;
int* p = new int;
dimensione fissa

liberata da sola
la liberi tu

sopravvive alla funzione
✓È proprio l'ultima riga che rende possibili le liste: un nodo creato dentro una funzione continua a esistere anche dopo che la funzione è finita.

Array dinamici

SEZIONE 03 
int n;
cout << "Quanti valori? ";
cin >> n;

int* v = new int[n];   // n deciso ORA, non a compile-time

for (int i = 0; i < n; i++) {
  cout << "Valore " << i+1 << ": ";
  cin >> v[i];              // si usa come un array normale
}

int somma = 0;
for (int i = 0; i < n; i++) somma += v[i];
cout << "Media: " << (double)somma / n;

delete[] v;               // parentesi quadre OBBLIGATORIE
v = nullptr;

Cosa cambia davvero

Nessuno spreco e nessun limite artificiale: chiedi esattamente la memoria che ti serve, nel momento in cui scopri quanta te ne serve.

⚠Usare delete al posto di delete[] su un array è un errore grave: viene liberato solo il primo elemento. Il programma spesso non si blocca subito, ed è il peggio che possa capitare.

Il limite che resta

Un array dinamico ha comunque una dimensione fissata al momento della creazione. Per aggiungere un elemento in più devi allocare un array nuovo, ricopiare tutto e cancellare il vecchio.

➜Da qui nasce l'idea di lista concatenata: una struttura che cresce un pezzo alla volta, senza mai ricopiare nulla.

I due errori da conoscere

SEZIONE 03

Memory leak

Memoria allocata e mai restituita, perché hai perso l'unico puntatore che la raggiungeva. Resta occupata fino alla fine del programma.

int* p = new int(5);
p = new int(9);   // il primo indirizzo e' PERSO
// quei 4 byte non sono piu' raggiungibili
// ne' utilizzabili: leak.

// Corretto:
int* q = new int(5);
delete q;
q = new int(9);
delete q;
ⓘIn un esercizio scolastico non te ne accorgi. In un server che gira per settimane, un leak dentro un ciclo consuma tutta la RAM della macchina.

Dangling pointer

Il problema opposto: il puntatore esiste ancora ma la memoria è già stata liberata. Punta a una zona non più valida.

int* p = new int(5);
delete p;          // memoria restituita
cout << *p;       // p e' "dangling": errore
*p = 10;         // peggio ancora: scrivi dove non devi

// Corretto:
delete p;
p = nullptr;      // ora il test funziona
if (p != nullptr) cout << *p;
✗Fare delete due volte sullo stesso indirizzo (double free) è altrettanto grave. Azzerare il puntatore dopo il delete previene anche questo: delete nullptr è innocuo.

Puntatori a struct e operatore ->

SEZIONE 03

La scorciatoia indispensabile

Per accedere a un campo attraverso un puntatore servirebbero parentesi scomode. C++ offre l'operatore ->, che fa esattamente la stessa cosa.

struct Studente {
  string nome;
  int voto;
};

Studente* p = new Studente;

(*p).voto = 8;   // forma lunga
p->voto = 8;      // forma breve: IDENTICA
p->nome = "Luca";

cout << p->nome << " " << p->voto;

delete p;
⚠*p.voto non funziona: il punto ha priorità più alta dell'asterisco, quindi il compilatore legge *(p.voto). Servono le parentesi, o meglio ancora ->.
SE HAI...
USI...
Studente s;
s.voto
Studente* p;
p->voto

Da qui al nodo

Ora hai tutti i pezzi. Una struct può contenere un puntatore a una struct dello stesso tipo: è questo il mattone con cui si costruiscono liste, pile e code.

struct Nodo {
  int dato;
  Nodo* next;   // puntatore a un altro Nodo
};                // struct AUTOREFERENZIALE
ⓘPerché è legale usare Nodo dentro Nodo, se non è ancora finita di definire? Perché next è un puntatore: occupa sempre la stessa dimensione, qualunque cosa ci sia dall'altra parte. Un campo Nodo next; non compilerebbe.

La lista concatenata

SEZIONE 04

L'idea

Invece di tenere i dati uno accanto all'altro come in un array, ogni elemento (nodo) sta dove capita nello heap e tiene l'indirizzo del successivo. Basta conservare il puntatore al primo nodo — la testa — per raggiungerli tutti.

testa →
10next ●
→
25next ●
→
7next ●
→ nullptr 
struct Nodo {
  int dato;
  Nodo* next;
};

Nodo* testa = nullptr;  // lista VUOTA

// Un nodo creato a mano:
Nodo* n1 = new Nodo;
n1->dato = 10;
n1->next = nullptr;
testa = n1;              // lista di 1 elemento

Le due convenzioni da rispettare sempre

  • testa == nullptr significa lista vuota.
  • L'ultimo nodo ha next == nullptr: è così che si riconosce la fine.
✓Vantaggio: inserire un elemento costa sempre lo stesso, anche con un milione di nodi. Non si ricopia niente e non c'è nessun limite massimo.
⚠Prezzo da pagare: niente accesso diretto. Non esiste lista[7]. Per arrivare all'ottavo nodo devi attraversare i sette precedenti.

Inserimento in testa

SEZIONE 04 
// Restituisce la NUOVA testa della lista
Nodo* inserisciInTesta(Nodo* testa, int valore) {
  Nodo* nuovo = new Nodo;  // 1. creo il nodo
  nuovo->dato = valore;      // 2. riempio il dato
  nuovo->next = testa;       // 3. aggancio la vecchia testa
  return nuovo;                // 4. il nuovo E' la testa
}

// Uso nel main:
Nodo* testa = nullptr;
testa = inserisciInTesta(testa, 7);
testa = inserisciInTesta(testa, 25);
testa = inserisciInTesta(testa, 10);
// risultato:  10 -> 25 -> 7 -> nullptr
⚠L'ordine dei passi 3 e 4 non è invertibile. Se prima cambi la testa e poi agganci, perdi il resto della lista: tutti i nodi successivi diventano irraggiungibili.

Scansione e ricerca

SEZIONE 04

Il ciclo che userai ovunque

Si parte dalla testa con un puntatore d'appoggio e si avanza con p = p->next finché non si incontra nullptr. È il while tipico delle liste: imparalo a memoria.

void stampaLista(Nodo* testa) {
  Nodo* p = testa;     // mai muovere testa!
  while (p != nullptr) {
    cout << p->dato << " -> ";
    p = p->next;        // passo al successivo
  }
  cout << "nullptr\n";
}

int contaNodi(Nodo* testa) {
  int c = 0;
  Nodo* p = testa;
  while (p != nullptr) { c++; p = p->next; }
  return c;
}
bool cerca(Nodo* testa, int valore) {
  Nodo* p = testa;
  while (p != nullptr) {
    if (p->dato == valore) return true;
    p = p->next;
  }
  return false;     // arrivato in fondo: non c'e'
}

// Somma e massimo: stesso schema
int somma(Nodo* testa) {
  int s = 0;
  Nodo* p = testa;
  while (p != nullptr) { s += p->dato; p = p->next; }
  return s;
}
⚠Dimenticare p = p->next; dentro il while produce un ciclo infinito. È l'errore numero uno con le liste: se il programma si pianta, controlla prima di tutto questa riga.
ⓘConfronto con l'array: qui non serve un contatore come n. La lista sa da sola dove finisce, perché l'ultimo nodo punta a nullptr.

Cancellazione di un nodo

SEZIONE 04 
Nodo* cancellaValore(Nodo* testa, int valore) {
  Nodo* p = testa;
  Nodo* prec = nullptr;   // nodo PRECEDENTE a p

  // cerco, tenendo il passo indietro
  while (p != nullptr && p->dato != valore) {
    prec = p;
    p = p->next;
  }

  if (p == nullptr) return testa;  // non trovato

  if (prec == nullptr)
    testa = p->next;      // era il PRIMO nodo
  else
    prec->next = p->next; // scavalco p

  delete p;                // libero la memoria
  return testa;
}
⚠L'ordine è vincolante: prima si ricuce la catena, poi si fa delete. Se cancelli per primo, p->next legge memoria già liberata.

Cancellare significa far saltare il nodo alla catena: il precedente inizia a puntare al successivo.

// Svuotare tutta la lista a fine programma
Nodo* svuota(Nodo* testa) {
  while (testa != nullptr) {
    Nodo* tmp = testa;
    testa = testa->next;  // avanzo PRIMA
    delete tmp;             // cancello DOPO
  }
  return nullptr;
}

La Pila (Stack) — LIFO

SEZIONE 05

Last In, First Out

Una lista con una regola in più: si inserisce e si estrae solo da un capo, la cima. L'ultimo entrato è il primo a uscire, come in una pila di piatti.

cima →
7●
→
25●
→
10●
→null 
Nodo* push(Nodo* cima, int v) {
  Nodo* nuovo = new Nodo;
  nuovo->dato = v;
  nuovo->next = cima;
  return nuovo;        // = inserimento in testa
}

Nodo* pop(Nodo* cima) {
  if (cima == nullptr) return nullptr;
  Nodo* tmp = cima;
  cima = cima->next;
  delete tmp;
  return cima;
}

int leggiCima(Nodo* cima) { return cima->dato; }
bool vuota(Nodo* cima) { return cima == nullptr; }
// Uso tipico
Nodo* pila = nullptr;
pila = push(pila, 10);
pila = push(pila, 25);
pila = push(pila, 7);

while (!vuota(pila)) {
  cout << leggiCima(pila) << " ";
  pila = pop(pila);
}
// stampa:  7 25 10   (ordine INVERTITO)

Dove la incontri davvero

  • Il tasto Annulla di qualsiasi programma
  • Il pulsante Indietro del browser
  • Il controllo delle parentesi bilanciate in un'espressione
  • Lo stack delle chiamate: è così che il computer ricorda dove tornare quando una funzione finisce
⚠leggiCima e pop su una pila vuota sono errori: controlla sempre con vuota() prima.
ⓘNota la coerenza con il vostro stile: le funzioni ricevono e restituiscono il puntatore aggiornato, senza parametri per riferimento. Più avanti, con le classi, tutto questo finirà dentro un oggetto Pila.

La Coda (Queue) — FIFO

SEZIONE 05

First In, First Out

Come la fila alla posta: si entra in fondo e si esce dalla testa. Servono quindi due puntatori, tenuti insieme in una struct.

testa →
10●
→
25●
→
7●
→null ← fondo 
struct Coda {
  Nodo* testa;   // si ESTRAE da qui
  Nodo* fondo;   // si INSERISCE qui
};

Coda creaCoda() {
  Coda c;
  c.testa = nullptr;
  c.fondo = nullptr;
  return c;
}
✓Tenere anche fondo serve a inserire senza scorrere tutta la lista: l'inserimento resta immediato anche con migliaia di elementi.
Coda enqueue(Coda c, int v) {
  Nodo* nuovo = new Nodo;
  nuovo->dato = v;
  nuovo->next = nullptr;   // va in FONDO

  if (c.fondo == nullptr)
    c.testa = nuovo;        // coda era vuota
  else
    c.fondo->next = nuovo; // aggancio in fondo

  c.fondo = nuovo;
  return c;
}

Coda dequeue(Coda c) {
  if (c.testa == nullptr) return c;
  Nodo* tmp = c.testa;
  c.testa = c.testa->next;
  if (c.testa == nullptr)
    c.fondo = nullptr;      // era l'ULTIMO
  delete tmp;
  return c;
}
⚠I due if sono i casi limite che quasi tutti dimenticano: coda vuota in inserimento e coda che si svuota in estrazione. Senza il secondo, fondo resta a puntare un nodo cancellato.

Dove la incontri

Coda di stampa, richieste a un server web, messaggi in arrivo, gestione dei processi del sistema operativo: ovunque conti rispettare l'ordine di arrivo.

Dove si va adesso
